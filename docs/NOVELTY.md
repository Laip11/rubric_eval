# MCCR 创新性横向比较（仅 training-free 设定）

> **2026-11-08 更新：主方法已改为 MCCR-ME（最小证据集合）**，见 `new_our_method.md` §5。第 0 节是针对 ME 的定位；第 1–5 节是对 v2 的分析，其中关于 RRD、OpenRubrics 等工作的比较对 ME 同样适用。

## 0. MCCR-ME 的定位

| 维度 | RRD | RubricHub / MRRG | OpenRubrics CRG | Chasing the Tail | **MCCR-ME** |
|---|---|---|---|---|---|
| 优化目标 | 区分度：分解过于宽松的准则，过滤错向准则 | 覆盖：多来源合并 | 对比：由偏好对得到规则和原则 | 尾部区分：top-2 差异 | **最小证据：扎根 + 必要 + 无冗余 + 充分** |
| 如何判定一条准则该留 | 弱 vs 强偏好方向 | 不判定（合并） | 偏好标签一致性（需要标签） | 不判定 | **单违反见证回答 + 正反两序裁判**，测试时不需要标签 |
| 如何判定集合够不够 | 不判定 | 不判定 | 不判定 | 迭代细化 | **反例搜索（CEGIS）：满足全部准则却更差 ⇒ 补充遗漏要求** |
| query 与回答的作用 | 回答驱动 | 回答驱动 | 回答对驱动 | 回答驱动 | **query 视图提供扎根候选（显式要求有原文片段并经校验）；响应视图只补充隐含要求，补充项必须通过必要性检验** |
| 所有探测都满足的必要准则 | 会被视为无区分度 | 保留但不区分 | — | — | **显式要求直接保留；隐含要求由见证测试判定，而不是由探测方差判定** |

**可主张的贡献（未检索到直接先例，写作时用“to our knowledge”）：**
1. 把准则构造表述为最小证据集合（极小充分条件），并给出三个可以经验检验的性质。
2. 用**单违反见证**做必要性检验：把“必要”从“有区分度”中分离出来。
3. 用**反例搜索**做充分性检验：一个满足全部准则却更差的回答，就是 rubric 缺少某项要求的直接证据。
4. **query 视图与 query+response 视图的对比**规则：显式 / Q∩R / Q-only / R-only 四类分别采用不同的举证责任。

**需要实验支撑的点：**
- `--me-necessity witness / judgment / hitting_set / none` 四种估计器的比较，以及 `--me-sufficiency off` 的消融；
- 在 RubricBench 上的专家准则召回率与精确率（最小性应提高精确率，同时不明显降低召回率）；
- 见证回答质量的人工抽检：是否“只违反了一条”；
- 与 RRD 在同探测、同算力条件下的比较。

## 2. 哪些不是创新（必须明确引用、不能当贡献写）

- **用回答来暴露准则：** RLCF、RubricHub、RRD、Chasing the Tail 都已经这样做。
- **用强/弱模型判断准则方向、用白化抑制相关准则重复计分：** 基本就是 RRD 的做法，只是 MCCR 把硬过滤换成了连续对齐度。
- **硬约束和软原则的二分：** OpenRubrics 已经提出。
- **多次采样或多来源准则聚合：** RubricHub、MRRG、GenRubric（后者是训练型，只在动机上相关）都有。

如果论文把以上任何一点写成主要贡献，审稿人很可能会判为 incremental。

## 3. 可能构成贡献的三点（未检索到直接先例）

1. **单缺陷反事实探测作为免标签的方向监督。**
   - 做法：由生成器把强探测改写成只含一个实质缺陷、风格和长度不变的版本，用“原始 ≻ 反事实”来验证每条准则的方向。
   - 与已有工作的区别：已有工作里扰动主要用于测试裁判的鲁棒性（如 [2601.08843](https://arxiv.org/abs/2601.08843)，用同义词、错别字等扰动），或用于训练奖励模型；我们没有找到在推理时、不用标签、用它来校验准则的工作。
   - 优势：相比 RRD 的强/弱对，反事实对控制了风格和长度，能把“偏好风格”的准则与“偏好正确性”的准则分开。
2. **以跨视图共识统计量把准则显式分为 core 和补充两层。**
   - 区别：RubricHub 和 MRRG 只把多来源准则合并成一个平铺的集合，没有用支持度来定义层级。
   - 风险：已有研究指出，LLM 之间的共识不等于与人类一致（[2606.03043](https://arxiv.org/abs/2606.03043)）。因此这一点必须用 RubricBench 专家准则召回率（H1）来证明共识确实提高了覆盖，而不能只靠直觉论证。
3. **带证明的分层聚合。**
   - 内容：在离散分数下，补充准则永远推翻不了 core 上的差距，把“核心要求优先”变成一个可检验的性质。
   - 区别：OpenRubrics 有二分但没有这样的保证；PAOR 只对均匀权重成立，v2 把它推广到加权 core。

## 4. 主要风险与对策

最大的风险是整体被看作“RRD + 共识聚类 + 反事实”的工程组合。建议采取以下对策：

- **叙事主线：** 以“**免标签的准则方向校验（单缺陷反事实）+ 核心优先的分层聚合**”为主线；多视图共识作为提高覆盖的手段，而不是主要卖点。
- **必须有的实验（代码已就绪）：**
  1. 与 RRD 在同探测、同裁判下正面对比：`mccr_v2_vs_rrd.json`。
  2. 反事实的独立贡献：消融 `_roles`（只用强/弱对）、`_cf`（只用反事实对）和完整 v2。另外，抽样人工核查约 100 条反事实，确认“恰好一个缺陷、风格未变”。
  3. 分层的作用：在 LLMBar Adversarial 和 RM-Bench Hard 上比较 `_linear` 和 `_gated`。这两个数据集正是“表面好、核心错”的场景，与 H2 对应。
  4. 共识带来的覆盖：在 RubricBench 上比较专家准则召回率，对照 `rubric_query`、`rubric_resp`、`rrd`、`_legacyviews`。
  5. 增益不是靠更多调用换来的：准确率–算力曲线，与 `direct_k`、`sc_principles@k`、不同 N 的 RRD 放在一起比较。
- **能加分的补充分析：**
  - 反事实缺陷类型（约束违反 / 事实错误 / 遗漏 / 拒答错误）与准则被过滤之间的关系；
  - 被判为错向的 core 准则的实例分析，例如“偏好冗长”“偏好格式”这类准则。

## 5. 一句话定位（建议）

> 不需要任何偏好标签或训练，MCCR 用单缺陷反事实探测为每条生成准则提供方向证据，并用一个可证明“核心要求优先”的分层聚合来使用这些准则。在同探测、同裁判、同算力的条件下与 RRD 等方法对比。
